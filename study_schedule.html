第 1–2 周

1. Tokenization & Transformer 基线

对应 Lecture 1–4：overview、tokenization、resource accounting、architecture、attention/MoE
  • 观看 playlist 前 4 讲；读 lecture materials。
  • 完成 A1 的 tokenizer、Transformer、optimizer；先用 TinyStories 跑通。
  • 复习 KV cache：每层 K/V 的 shape、dtype、随序列长度的线性增长。
产出
记录 baseline：模型配置、prefill/decode latency、显存峰值、PPL；画出 KV cache memory 公式。
第 3–4 周

2. GPU、Kernel、Triton 与性能测量

对应 Lecture 5–6：GPUs/TPUs、kernels、Triton
  • 完成 A1 收尾；观看 Lecture 5–6。
  • 使用 PyTorch profiler、Nsight Systems/Compute 或等价工具建立测量习惯。
  • 完成小型 Triton kernel；理解 memory-bound 与 compute-bound。
产出
建立 benchmark harness：固定 prompt、batch、sequence length，输出 CSV/JSON；避免只报告平均值，加入 P50/P95/P99。
第 5–6 周研究切入点

3. Parallelism、Scaling 与 Inference

对应 Lecture 7–11：parallelism、scaling laws、inference
  • 完成 A2 的 profiling、FlashAttention/分布式相关部分；观看 Lecture 7–11。
  • 系统区分 prefill 与 decode：算力需求、内存带宽、KV cache 读写路径。
  • 学习 continuous batching、paged attention、tensor parallel 对 KV 的影响。
产出
写 2 页 system note：为什么 decode 阶段会受 KV cache 和 HBM bandwidth 约束？列出 3 个可验证假设。
第 7–8 周

4. Evaluation + CS336 A3 Scaling

对应 Lecture 9–12；完成 Assignment 3
  • 完成 scaling-law 实验，理解 compute-optimal 与 extrapolation 的限制。
  • 为推理系统定义 workload：短/长上下文、不同 batch、不同并发。
  • 建立 quality harness：固定模型、数据集和解码参数。
产出
一份 baseline report：吞吐（tokens/s）、TTFT、TPOT、显存占用、PPL/任务准确率和实验配置。
第 9–10 周系统方向

5. Data、训练后处理与长上下文

对应 Lecture 13–17：data、filtering/dedup、SFT/RL、multimodality
  • 观看剩余 CS336 讲次；A4/A5 选择性完成，优先理解数据和评估流程。
  • 补充 long-context、RoPE/位置编码、KV cache quantization 的背景。
  • 开始文献矩阵：方法、offload 层级、调度策略、硬件、指标、限制。
产出
至少 10 篇论文的表格；明确你的 baseline、对比方法和尚未解决的 gap。
第 11–12 周

6. KV Cache Offloading 基线实现

研究 Sprint 1 · GPU ↔ CPU/NVMe
  • 实现 layer-wise/chunk-wise cache eviction 与恢复；先做同步正确性版本。
  • 比较 pinned CPU memory、普通 CPU memory、NVMe 的 copy 路径。
  • 加入异步 prefetch/eviction，记录 overlap、queue depth 和 stall。
产出
可复现 baseline repo + 一张 Pareto 图：显存节省 vs TPOT/P95 latency vs quality。
第 13–14 周

7. CXL 内存系统基础

研究 Sprint 2 · CXL 2.0/3.0、.cache hierarchy、带宽与延迟
  • 阅读 CXL Consortium 的公开资料，理解 CXL.io、CXL.cache、CXL.mem 与 Type-3 device。
  • 把 CXL memory 视为 tiered memory：容量、带宽、访问延迟、NUMA/拓扑。
  • 用 trace/replay 或 simulator 做第一版 latency-bandwidth 模型。
产出
画出 GPU–HBM–CPU DRAM–CXL memory 的数据路径；给出你的假设和参数来源。
第 15–16 周

8. 面向 CXL 的 KV Cache 调度器

研究 Sprint 3 · locality、prefetch、compression、admission
  • 设计 cache tier policy：hot KV 留在 HBM，warm KV 放 CXL，cold KV 压缩或淘汰。
  • 对比 FIFO/LRU、attention-score、预测式和 budget-aware 策略。
  • 加入多请求调度，测试长短请求混合、burst traffic 和高并发。
产出
一份 design doc：policy、数据结构、并发模型、故障/回退路径和复杂度。
第 17–20 周里程碑

9. 实验矩阵、消融与论文雏形

研究 Sprint 4 · 结果可信度优先
  • 至少 3 个模型规模、3 个上下文长度、3 种并发/批大小。
  • 消融：无 offload、CPU offload、CXL 模型、量化、prefetch、不同 eviction。
  • 报告均值与尾延迟，固定随机种子，记录硬件、软件版本和功耗/成本（若可得）。
产出
6–8 页 workshop-style paper：问题、系统、实验、局限、可复现说明；一次组会式 presentation。
第 21–24 周最终里程碑

10. 真实硬件验证与下一步研究计划

从模拟假设走向可验证系统
  • 如果能获得 CXL 设备：验证链路带宽、延迟、NUMA 亲和性和并发行为；否则明确 simulator-to-hardware gap。
  • 复现至少一个公开 baseline，并做端到端长上下文服务测试。
  • 整理 artifact：代码、配置、数据生成脚本、图表和 README。
最终产出
可公开的 artifact + 研究 proposal：核心 claim、实验计划、风险、预期贡献和后续 3 个月路线。

建议节奏：周一/二看 1–2 讲并做笔记；周三至周五实现；周末跑实验、写结论。你已完成 CMU 11-785，因此不必重新系统补深度学习；只在 profiler、GPU memory hierarchy、distributed systems、CXL 语义上定向补课。
